Standardized Generic CRUD Search API Contract

Identical signature and underlying implementation across all entities, varying only by Subject

Uniform Contract Specification

Rather than inventing disparate query parameters or custom controller endpoints for each entity, every manageable entity follows the exact same search signature:

// Uniform Search Endpoint Pattern
POST /api/admin/{subject}/search
Headers: X-Trace-Id, Authorization: Bearer <token>
// Request Payload Contract (Generic across all subjects):
{ "filters": [ { "field": "status", "operator": "EQUALS", "value": "ACTIVE" }, { "field": "createdAt", "operator": "BETWEEN", "value": ["2026-01-01", "2026-11-07"] } ], "searchQuery": "admin", "logic": "AND", "sorts": [{ "field": "createdAt", "direction": "DESC" }], "page": 0, "size": 20, "traceId": "tr-9481-ac2d" }

Supported operators: EQUALS, NOT_EQUALS, CONTAINS, STARTS_WITH, GREATER_THAN, LESS_THAN, IN, BETWEEN, IS_NULL.

Shared Generic Implementation Architecture

The entire search pipeline uses a single reusable abstraction in the persistence layer:

  1. GenericSpecificationBuilder<T>: Dynamically constructs a Spring Data JPA Specification<T> from the incoming JSON filter tokens via Criteria API.
  2. BaseSearchService<T, ID>: Handles tenant isolation guards, authorization scope checks, and pagination cursor execution.
  3. Standardized Envelope: Every response returns PagedApiResponse<T> containing:
    { success: true, traceId: "...", subject: "users", page: 0, size: 20, totalElements: 1250, totalPages: 63, data: [ ... ] }
Single Implementation JPA Criteria API Zero Duplication Uniform Envelopes

Intelligent Multi-Provider Best-Choice SMS Engine

Dynamic gateway orchestrating multiple providers based on cost, delivery success rate, carrier latency, and circuit breaking

Intelligent Routing & Failover Architecture

Rather than locking the application to a single SMS vendor, AppService implements a pluggable Multi-Provider Smart SMS Gateway (`SmsProviderGateway`). When a dispatch request is received:

  • Real-Time Health & Latency Scoring: Calculates rolling delivery rate and acknowledgment latency per provider (e.g. Twilio, Kavenegar, FarazSms, Infobip, AWS SNS).
  • Cost & Carrier Optimization: Evaluates destination prefix (domestic vs international) and selects the provider with the lowest cost per delivered message.
  • Circuit Breaker & Instant Fallback: If Provider A fails 3 times consecutively or latency exceeds 1,200ms, the router instantly reroutes to Provider B without dropping the message.
  • Fast-Track OTP Priority: Authentication tokens bypass bulk promotional queues through a dedicated priority channel.
// Intelligent SMS Router Decision Pipeline
1. Inbound SMS: +98912XXXXXXX (Type: OTP_TOKEN)
2. Candidate Providers: [Kavenegar, FarazSms, Twilio]
3. Health Check: Kavenegar (Score: 99.4%, Latency: 320ms, Cost: $0.008)
4. Health Check: FarazSms (Score: 98.1%, Latency: 480ms, Cost: $0.009)
5. Decision: Kavenegar Selected → Dispatched (Trace: sms-7a1b)
6. Fallback Buffer: FarazSms armed if DLR not received in 3000ms

Dedicated Administrative Control Panels Specification

Eight specialized management dashboards designed for operator visibility and platform control

1. Audit Log Dashboard (Trace Filter Engine)

Provides deep query capabilities over immutable security and business event logs. Allows filtering by correlation tokens across distributed transactions.

  • Trace Filters: Query by traceId, correlationId, spanId, actor ID, client IP, action verb, and UTC date-time range.
  • Before/After Diff Inspector: Side-by-side JSON diff viewer highlighting modified fields with sensitive data and credentials automatically redacted.
Trace Field FiltersJSON DiffsTamper-Proof

2. Job Scheduler Management Panel

Clustered Quartz and Spring Scheduler dashboard giving full oversight over background batches and automated triggers.

  • Trigger Table: Displays cron expressions, previous fire time, next scheduled run, and node ownership.
  • Manual Controls: "Fire Now", "Pause Trigger", "Resume", and "Abort Active Thread".
  • Execution Logs: Historical duration charts, retry counts, and full stack-traces on error.
Clustered QuartzFire NowFailure Diagnostics

3. Mail Management Panel

Comprehensive email delivery and template administration console supporting multiple outbound SMTP and API transports.

  • Provider Setup: Configure primary and fallback SMTP / API credentials (SendGrid, SES, Mailgun).
  • Template Studio: Visual HTML/Jinja template editor with live preview, token placeholders (`{{resetLink}}`, `{{accountName}}`), and instant test-send dispatch.
  • Delivery Ledger: Monitor sent messages, bounce rates, spam complaints, and retry queues.
Multi-SMTPLive Template EditorBounce Analytics

4. SMS Management Panel

Control center for the Intelligent Multi-Provider SMS Engine. Configure vendor weights, pricing thresholds, and delivery rules.

  • Routing Strategy: Set active algorithm (Cost-Optimized, Latency-Optimized, or Balanced).
  • Carrier Health Monitor: Live status indicators for Kavenegar, FarazSms, Twilio, and AWS SNS.
  • Template & Test Utility: Regex pattern approval, phone number testing tool, and balance quota alerts.
Smart Routing PolicyVendor HealthBalance Quota

5. Monitoring & Operations Panel

Telemetry dashboard aggregating runtime application metrics, database connection pools, memory states, and health probes.

  • API Latency Percentiles: Real-time P50, P95, and P99 response durations across all REST endpoints.
  • Database Pool: HikariCP active connections, idle threads, pending acquires, and query latency.
  • JVM & Circuit Breakers: Heap utilization, garbage collection pause frequency, and Resilience4j circuit states.
Spring ActuatorHikariCP MetricsCircuit Breakers

6. Tenant Management Panel

Multi-tenancy administration console managing customer organizations and the dynamic Hybrid Isolation Model.

  • Isolation Strategy Picker: Assign tenant to Tier 1 (Shared DB column), Tier 2 (PostgreSQL Schema), or Tier 3 (Dedicated DB).
  • Provisioning Wizard: Automates Liquibase migrations for new schemas or databases upon tenant onboarding.
  • Quotas & Governance: Maximum registered users, document storage limits, API rate quotas, and tenant kill-switch.
Hybrid Strategy RouterSchema ProvisionerTenant Quotas

7. Client & API Key Management Panel

Administration panel for OAuth2 / OIDC client applications, third-party API consumers, and automated service accounts.

  • Client Registration: Issue Client IDs and cryptographically secure secrets (stored as SHA-256 hashes).
  • Grant Types & Scopes: Configure PKCE requirement, Authorization Code, Client Credentials, and specific permission scopes.
  • Rate Limits & Expiration: Token TTL, rotation schedules, and per-client token bucket rate limiters.
OAuth2 ClientsPKCE EnforcementHashed Secrets

8. AI Agent Infrastructure & Tool Plane

Specialized control plane and execution harness enabling autonomous AI coding and operational agents to safely interact with the application.

  • Model Context Protocol (MCP) Endpoints: Exposes structured tool interfaces, OpenAPI schemas, and read-only resource feeds for AI agents.
  • Role-Scoped Agent Tokens: AI agents operate under least-privilege service accounts with strict blast-radius controls.
  • Execution Audit & Guardrails: Every AI tool call, argument payload, generated diff, and token count is permanently recorded in the audit trail. Destructive actions require human approval tokens.
